Introduction¶

1. Overview¶

Cost constrained flux balance analysis (ccFBA) in Python. This is a port of the R package sybilccFBA (version 3.0.2, by Abdelmoneim Amer Desouki). It is built on COBRApy and optlang instead of sybil.

This manual is based on the R help pages in R/sybilccFBA/man/*.Rd. Each R help page has a section here that describes the Python function, or says what replaces it. Each section also gives the R usage for comparison.

What the package does¶

Flux balance analysis (FBA) finds the fluxes of a metabolic model at steady state (Orth, Thiele & Palsson 2010). Cost constrained FBA also limits the fluxes by the amount of enzyme the cell can afford. It needs three inputs besides the model:

  • kinetic data: the turnover number kcat of the enzyme of each reaction,
  • the molecular weight (MW) of each protein,
  • the gene-protein-reaction (GPR) rules of the model.

Two constraints are added to FBA:

v_i <= kcat_i * g_i        # flux <= turnover number x enzyme concentration
sum_g (MW_g * g_g) <= C    # total enzyme mass <= budget C (0.27 g/gDW for E. coli)

The package implements:

  1. MOMENT (MetabOlic Modeling with ENzyme kineTics), Adadi et al. (2012): cfba_moment, and cfba_moment_pw written like the original MATLAB implementation.
  2. ccFBA, an improvement of MOMENT (Desouki 2016):
    • multi-functional enzymes: an enzyme that catalyzes several reactions must share its concentration between them (ccFBA_mr);
    • only the cheapest isoenzyme of each reaction is used (getGpr1iso);
    • optional protein complex stoichiometry (getccFBA_mat, getccFBA_sol);
    • new in Python: ccFBA_iso keeps all the isoenzymes and allocates each gene to the complexes that use it, instead of choosing one isoenzyme with getGpr1iso.

2. Inputs, units and conventions¶

The R help pages describe the same arguments (model, mod2, Kcat, MW, RHS, medval, cpx_stoich, ...) on every page. This page describes their Python formats once. The function pages link here.

Units¶

Quantity Symbol Unit
flux v mmol/gDW/h
turnover number, input kcat 1/s (converted to 1/h inside the functions: × 3600)
turnover number for missing values medval 1/h (not converted, e.g. 3600*22.6)
enzyme (gene) concentration g mmol/gDW
molecular weight MW g/mmol (= kDa), e.g. 89.12 for b0002
budget of metabolic protein C, RHS g protein/gDW (0.27 for E. coli)
protein cost (molecular crowding) MC = MW * g g protein/gDW

The R help pages give the unit of MW as g/mol. The values in the data sets (mw, mw_iML1515, yst_mw, data/*MW.csv) are in g/mmol (kDa), which is what the budget constraint needs (MW * g in g/gDW). calc_MW returns g/mol, so divide its output by 1000: pd.DataFrame({'gene': geneCnt['Synonym'], 'mw': geneCnt['mw'] / 1000}).

Irreversible model (mod2)¶

In R, mod2 is the irreversible model of model (sybil's mod2irrev). In Python:

  • cfba_moment and ccFBA_mr have no mod2 argument. They work on a copy of the cobra model and use its bounds. A reversible reaction gets one kcat constraint on its forward variable and one on its reverse variable.
  • getccFBA_mat, getccFBA_sol, simulate_EColi and simGeneOverExpr (with getccFBA_sol) use an IrrevModel made by mod2irrev(model). Reversible reactions are split in <id>_f and <id>_b. The bounds of the fluxes are taken from mod2.lowbnd and mod2.uppbnd, so you can change them there before solving, as in R.

Kinetic data (Kcat)¶

A pandas.DataFrame with one row per reaction and direction:

Column Content
rxn_id reaction id
val kcat in 1/s
dirxn 1 forward, -1 reverse direction
src optional: source of the value (used in getccFBA_mat outputs, kcat_src_ir)

Reactions without a value for a direction use medval (in 1/h). The default is the median of val (after conversion to 1/h).

The functions read the table in different ways:

Function Column lookup Matching of rxn_id
cfba_moment, ccFBA_mr val must be the second column (it is converted by position) rxn_id must be 'R_' + reaction id. The prefix is added to the reaction id unless it already starts with R_
getccFBA_mat, getccFBA_sol, simulate_EColi by name reaction id with or without the R_ prefix

data/Ecoli_kcat.csv and the R data set kcat already have the R_ prefix. The kcat table allKcats_upd34_dd_h.csv (column ijo_id) does not. To use it with cfba_moment or ccFBA_mr, add the prefix: kcat['rxn_id'] = 'R_' + kcat['rxn_id']. Otherwise all reactions silently get medval.

Molecular weights (MW)¶

A pandas.DataFrame. The first column is the gene id and the second column is the molecular weight in g/mmol. Column names do not matter (Synonym/mw, gene/mw, ...). If a gene appears more than once, the first row is used.

Genes without a molecular weight get no cost: they are left out of the budget constraint.

↑ Back to contents

Spontaneous reactions (s0001)¶

E. coli models use the pseudo gene s0001 for spontaneous reactions. It has no molecular weight in mw.

  • cfba_moment, ccFBA_mr: reactions whose whole GPR is s0001 are not constrained. Other reactions that contain s0001 (e.g. b0875 or s0001) use a variable g_s0001 that has no cost, so in practice these reactions are free. The R version removes s0001 from these rules (e.g. b0875 or s0001 becomes b0875) for the rule strings it knows. The Python version has the same list, but cobra writes the rules without parentheses (b0875 or s0001), so they do not match and are not changed.
  • cfba_moment_pw: s0001 is removed from the OR rules (e.g. b0875 or s0001 becomes b0875), as R does.
  • getccFBA_mat: getGpr1iso prefers terms with unknown MW, so s0001 is chosen for b0875 or s0001 and the reaction has no cost (as in R).
  • ccFBA_iso: s0001 is a gene without MW (no cost), unless it is removed with rm_genes=['s0001'].
  • The R examples add s0001 with a very small MW (0.001) to the MW table.

Budget (RHS) and objective¶

  • RHS is the budget C: sum(MW_g * g_g) <= RHS.
  • cfba_moment, ccFBA_mr: when RHS is None no budget constraint is added and objVal is ignored, so the result is an FBA with the kcat constraints only.
  • getccFBA_mat: when RHS is None the problem is to minimize the budget needed to reach the objective value objVal (default: the FBA optimum).

Gene concentration bounds (geneConcLB, geneConcUB)¶

Lower and upper bounds of the gene concentrations, in mmol/gDW. The defaults are 0 and 1000. You can give a dict {gene_id: value} to all functions. getccFBA_mat and getccFBA_sol also accept a list in the order of model.genes. For example, you can simulate over expression with a lower bound (see simGeneOverExpr).

Solver¶

The R functions have a solver argument (glpkAPI, cplexAPI, ...). In Python the argument is accepted but not used:

  • cfba_moment and ccFBA_mr use the solver of the model (model.solver). To change it: model.solver = 'glpk'.
  • getccFBA_mat / solve_ccFBA_mat use cobra's default solver (cobra.Configuration().solver), or the interface argument of solve_ccFBA_mat.

3. cfba_moment: MOMENT method¶

R help page: man/cfba_moment.Rd. Python: ccfbapy/cfba_moment.py, function cfba_moment().

Description¶

Uses the GPR rules, kcat values and molecular weights to compute fluxes with the MOMENT method (Adadi et al. 2012). Each reaction with a GPR gets a kcat constraint on its flux. The total mass of the enzymes is limited by the budget RHS. The objective of the model (e.g. growth) is maximized.

Details¶

Main steps:

  1. Add a concentration variable g_<gene> for every gene of the model.
  2. For each selected reaction, parse the GPR rule.
  3. Add variables and constraints according to the rule (table below).
  4. Add the budget ("solvent capacity") constraint MW: sum(MW_g * g_g) <= RHS, for the genes that have a molecular weight.

Variables and constraints for each type of GPR rule:

GPR rule Variables Constraints
one gene A <rxn>_kcat: v <= kcat * g_A
complex A and B cpx_<rxn> <rxn>_kcat: v <= kcat * cpx; <rxn>_A: cpx <= g_A; <rxn>_B: cpx <= g_B
isoenzymes A or B <rxn>: v <= kcat * (g_A + g_B)
(A and B) or C cpx_<rxn>_<p> for AND term p (0-based) <rxn>: v <= kcat * (cpx_<rxn>_0 + g_C); Aux_<n>: cpx <= g for each gene of the term

A reversible reaction (lower bound < 0) gets the same constraint for its reverse variable, with the reverse kcat (dirxn = -1): <rxn>_b_kcat or <rxn>_b.

An OR with more than two terms is written as one constraint, not pairwise as in the original MATLAB implementation of MOMENT (see cfba_moment_pw, which also works on the irreversible model and removes s0001 from the rules).

The constraints are added to the solver problem of a copy of model. They are not added as cobra reactions. If the copy already has an enzyme layer from an earlier call, it is removed first (see remove_enzyme_layer).

In R, when RHS is NULL the problem becomes: find the minimum budget that gives objVal (default: FBA optimum). The Python version does not implement this. With RHS=None it solves FBA with the kcat constraints only. Use getccFBA_mat with RHS=None for the minimum budget.

Examples¶

Python version of the first example of the R help page: iAF1260 from the R data set, growth on glucose with oxygen, ATPM lower bound 0. In R the bounds are changed in mod2. In Python they are changed in the cobra model.

from ccfbapy import datasets
from ccfbapy import cfba_moment

model = datasets.load_model('iAF1260')       # R: data(iAF1260)
mw = datasets.load_dataset('mw')             # R: data(mw)
kcat = datasets.load_dataset('kcat')         # R: data(kcat)

model.reactions.get_by_id('R_EX_glc_e_').lower_bound = -1000   # uppbnd(mod2)[R_EX_glc_e__b] = 1000
model.reactions.get_by_id('R_EX_glyc_e_').lower_bound = 0      # uppbnd(mod2)[R_EX_glyc_e__b] = 0
model.reactions.get_by_id('R_EX_ac_e_').lower_bound = 0
model.reactions.get_by_id('R_EX_o2_e_').lower_bound = -1000
model.reactions.get_by_id('R_ATPM').lower_bound = 0

4. cfba_moment_mr: MOMENT with multi-functional enzymes (ccFBA_mr)¶

R help page: man/cfba_moment_mr.Rd. Python: ccfbapy/ccFBA_mr.py, function ccFBA_mr() (the R name is cfba_moment_mr).

Description¶

Computes fluxes like cfba_moment (GPR, kcat, molecular weights), but takes multi-functional enzymes into account. In MOMENT, a protein i that catalyzes several reactions can use its whole concentration g_i for each of them. Here, when protein i takes part in more than one reaction, there is an auxiliary concentration variable x_ij for each of these reactions j. The x_ij replace g_i in the kcat constraint of reaction j. Their sum is bounded by the total concentration g_i, which is the variable in the budget constraint.

Details¶

Main steps:

  1. Add a variable g_<gene> for every gene that is in at least one selected reaction. If the gene is in n > 1 selected reactions, also add one variable gr_<gene>_<rxn> for each of them.
  2. For each selected reaction, parse the GPR rule.
  3. Add the kcat constraints as in cfba_moment. For a multi-functional gene, the constraint uses gr_<gene>_<rxn> instead of g_<gene>.
  4. Add the multi-functional enzyme constraints mfe_<gene>: sum_rxn gr_<gene>_<rxn> - g_<gene> <= 0.
  5. Add the budget constraint MW: sum(MW_g * g_g) <= RHS.

In R, the mfe_ constraints are equalities (sum = g). In Python they are <=. The growth rate is the same, but with a lower bound on g_<gene> (over expression) the Python version can leave part of the protein unused.

With the same RHS, ccFBA_mr predicts lower growth rates than cfba_moment, because the capacity of multi-functional enzymes is shared between their reactions (iAF1260 on glucose in the test notebooks: 0.26 vs 0.47 1/h).

5. cfba_moment_pw: MOMENT with pairwise OR¶

R help page: man/cfba_moment_pw.Rd. Python: ccfbapy/cfba_moment_pw.py, function cfba_moment_pw().

Description¶

Computes fluxes with the MOMENT method (GPR, kcat and molecular weights), written like the original MATLAB implementation of MOMENT. It works on the irreversible model, and a GPR rule with more than two isoenzymes (OR terms) is written as a chain of pairwise sums.

Details¶

The function works on the irreversible model. The kcat of a backward reaction <id>_b is the value of <id> with dirxn = -1; the other reactions use dirxn = 1. Reactions without a value use medval.

Main steps:

  1. Add a variable g_<gene> for every gene except s0001.
  2. For each selected reaction, parse the GPR rule of its original reaction. Reactions without a GPR, or with the rule s0001, are not constrained. The isoenzyme s0001 is removed from OR rules (e.g. b0875 or s0001 becomes b0875). R does the same for the rule strings of iAF1260 and iJO1366 that it knows.
  3. Add variables and constraints according to the rule (table below).
  4. Add the budget ("solvent") constraint MW: sum(MW_g * g_g) <= RHS. When objVal is given, add ObjC_: objective >= objVal, and minimize sum(MW_g * g_g) instead.

Constraints for each type of GPR rule:

GPR rule Constraints
one gene A rkcat_<rxn>: v <= kcat * g_A
complex A and B rkcat_<rxn>: v <= kcat * cpx_<rxn>; min_<gene>_<rxn>: cpx <= g for each gene
two isoenzymes A or B rkcat_<rxn>: v <= kcat * (g_A + g_B)
more isoenzymes A or B or C or D AuxOR_<rxn>_1: auxOR_1 <= g_A + g_B; AuxOR_<rxn>_2: auxOR_2 <= g_C + auxOR_1; rkcat_<rxn>: v <= kcat * (g_D + auxOR_2)

An AND term of an OR rule gets a variable cpx_<rxn>_<p> (term p, 0-based), with the rows min_<gene>_<rxn>_<p>. The terms are chained in the order of their columns (genes first, in the order of the model, then the complexes), as in R.

The chain is equivalent to v <= kcat * (g_A + g_B + g_C + g_D), which cfba_moment writes in one row. pairwise=False writes the single row and gives the same optimum.

Differences from R¶

  • The problem is built as a matrix and solved with solve_ccFBA_mat, so the result can be solved again with other bounds.
  • The kcat direction comes from the irreversible model (is_bwd), not from the _f/_b suffix of the id. Kcat ids are matched with or without the R_ prefix.
  • s0001 is removed from all OR rules, not only from the rule strings that R knows.
  • The rules are parsed with cobra (disjunctive normal form), so nested rules like A and (B or C) are expanded. R splits the rule text on or/and, which assumes rules that are already in this form.
  • When neither RHS nor objVal is given, there is no budget constraint (R stops with an error). The default selected_rxns also works when mod2 is not given (R uses mod2 before making it).
  • The LP file of verboseMode > 2 is not written; use res['prob'].to_lp().

6. getGpr1iso: choose the cheapest isoenzyme¶

R help page: man/getGpr1iso.Rd. Python: ccfbapy/gpr1iso.py, function getGpr1iso().

Description¶

Preprocessing of the model for getccFBA_mat. The function computes the molecular weight of every enzyme (gene or complex) in each GPR rule. For each reaction it keeps only the isoenzyme with the smallest molecular weight, so the ORs are removed from the GPR rules.

↑ Back to contents

Arguments¶

↑ Back to contents

Details¶

Each GPR rule is written in disjunctive normal form (OR of AND terms). The rule gets one of four types:

gprtype Rule Example
r1g one gene b0001
r1cpx one complex b0001 and b0002
rmg isoenzymes, each one gene b0001 or b0002
rmcpx isoenzymes, at least one complex (b0001 and b0002) or b0003

The molecular weight of a term is sum(MW_gene * stoich_gene). It is sum(MW_gene) when the complex is not in cpx_stoich. For each reaction with more than one term, the term with the smallest MW is kept. If two terms have the same MW, the first one is kept. As in R, a term with an unknown MW (a gene that is not in MW, e.g. s0001) is preferred, because R's min() of a group with NA is NA. The function warns about genes without a molecular weight.

A single-gene term gets the stoichiometry 1 unless cpx_stoich gives another value, e.g. 2 for a homodimer.

7. getccFBA_mat: ccFBA problem as a constraint matrix¶

R help page: man/getccFBA_mat.Rd. Python: ccfbapy/getccFBA_mat.py, functions getccFBA_mat() and solve_ccFBA_mat().

Description¶

Given kcat values (1/s), molecular weights and, optionally, the stoichiometry of protein complexes, builds a ccFBA problem (maximize the objective, e.g. biomass) as a constraint matrix. Improvements over MOMENT:

  1. multi-functional enzymes: a gene that catalyzes n > 1 reactions gets one variable per reaction, and their sum equals the gene concentration;
  2. one enzyme (the cheapest isoenzyme, see getGpr1iso) per reaction. This removes the under estimation of the cost of rules like (A and B) or (A and C);
  3. optional protein complex stoichiometry.

ccFBA_iso removes the under estimation of point 2 without removing isoenzymes, by allocating each gene to the complexes that use it.

The matrix is built once and can be solved many times with other flux bounds, e.g. for several carbon sources (see simulate_EColi). Use solve_ccFBA_mat to solve it.

9. ccFBA_iso: isoenzymes without getGpr1iso (gene allocation)¶

No R help page: new in the Python version. Python: ccfbapy/ccFBA_iso.py, functions ccFBA_iso() and getccFBA_iso_mat().

Description¶

Cost constrained FBA in which the concentration of each gene is allocated to the enzymes that use it. This solves the under estimation of the cost of rules like (A and B) or (A and C) without getGpr1iso. The isoenzymes are kept, and the LP chooses between them (or uses a mixture). The function also includes multi-functional enzymes and the stoichiometry of protein complexes, like getccFBA_mat.

↑ Back to contents

The problem¶

In MOMENT (cfba_moment) each term of a rule gets its own limit. For (A and B) or (A and C):

v <= kcat * (cpx1 + cpx2)
cpx1 <= g_A,  cpx1 <= g_B          (complex A-B)
cpx2 <= g_A,  cpx2 <= g_C          (complex A-C)

Both complexes can use the whole concentration of A, so A is counted once but used twice. The enzyme is cheaper than it really is, and the flux is over estimated. ccFBA_mr shares a gene between reactions, but not between the complexes of the same reaction, so it has the same problem.

getccFBA_mat avoids it with getGpr1iso: before the problem is built, each reaction keeps only its cheapest isoenzyme (smallest molecular weight). This is a preprocessing heuristic:

  • the other isoenzymes are removed from the model. If a gene of the chosen isoenzyme is knocked out or limited (geneConcUB), the reaction is blocked or limited, although the other isoenzymes could catalyze it;
  • the choice is made from the molecular weights only, before the problem is solved. It cannot depend on the condition, and mixtures of isoenzymes are not possible.

↑ Back to contents

The formulation¶

Every term t of the rule of reaction r (a gene or a complex) is an enzyme with its own concentration e_rt. The concentration of each gene is the sum of its uses:

v_r  <= kcat_r * sum_t e_rt                                  for each direction of r (own kcat)
sum_{(r,t) that contain g} st_gt * e_rt  =  g_g              for each gene g
sum_g MW_g * g_g  <=  C

st_gt is the number of subunits of gene g in enzyme t (from cpx_stoich; 1 by default).

  • A subunit shared by several complexes, of the same or of different reactions, is counted once for each complex. The cost is never under estimated.
  • An enzyme that catalyzes several reactions gets one e_rt per reaction, and they share the gene: this is the multi-functional enzyme constraint.
  • The problem is still an LP. The isoenzymes are chosen by the optimization, for each condition.

Every solution of getccFBA_mat is also a solution of this problem (set the other isoenzymes to 0). Every solution of this problem is a solution of ccFBA_mr and MOMENT (set each complex variable to its enzyme). So, with the same inputs, the growth rates are ordered:

getccFBA_mat  <=  ccFBA_iso  <=  ccFBA_mr  <=  cfba_moment

11. simGeneOverExpr: over expression of one gene¶

No R help page. R source: R/OverExpr/simGeneOverExpr.R (test: R/OverExpr/test_simGeneOverExpr.R, kcat file R/OverExpr/kcat2). Python: ccfbapy/simGeneOverExpr.py, function simGeneOverExpr().

Description¶

Simulates the over expression of one gene with ccFBA (Tin Y Pang). The gene gx must use at least the fraction y_pct of the budget C. Then the fluxes of the enzymatic reactions are fixed and the total flux is minimized.

↑ Back to contents

Usage¶

                runFVA=FALSE, fvaRxn=NULL, FUN=cfba_moment)

↑ Back to contents

Arguments¶

Argument Description
gx the gene to over express, e.g. 'b2323'
y_pct fraction of C that gene gx must use (at most 1), e.g. 0.05 for 5%
FUN ccFBA function: cfba_moment (default), ccFBA_mr or getccFBA_sol. It must return a dict with obj, status, rxnFlx and geneConc.
model cobra.Model
mod2 irreversible model, only passed to FUN when FUN has this argument (getccFBA_sol). Default there: mod2irrev(model).
Kcat, MW, selected_rxns, verboseMode, medval passed to FUN
RHS the budget C, required
solver passed to FUN when not None
objVal accepted for compatibility with R, not used

↑ Back to contents

Details¶

Steps (as in R):

  1. WTSol: call FUN without over expression. The protein cost (MC) of gx is its concentration × MW.
  2. If gx already uses at least y_pct of C, OExSol = WTSol and OverExprEff is False. Otherwise FUN is called again with the lower bound RHS * y_pct / MW on the concentration of gx (OverExprEff is True).
  3. Minimum total flux (sybil's algorithm "mtf"): the fluxes of the reactions that have at least one gene with a non-zero molecular weight, and of the objective reaction, are fixed to the fluxes of OExSol. Then the sum of the absolute fluxes of all reactions is minimized.

The fluxes are computed with the bounds of model (cfba_moment, ccFBA_mr) or of mod2 (getccFBA_sol). The minimum total flux step uses the bounds of model; the model is restored afterwards.

If gx has no concentration variable in the problem of FUN, the over expressed protein cannot catalyze any reaction. This happens with getccFBA_sol when the gene is not in the chosen isoenzyme of any reaction. In that case the protein only takes its part of the budget: FUN is called with RHS * (1 - y_pct). R stops with an error in this case.

With ccFBA_mr, the sum of the parts of a multi-functional enzyme is <= its total concentration in Python (= in R). Part of the over expressed protein may therefore stay unused.

Description¶

Makes an irreversible version of a cobra model, as sybil's mod2irrev. A reaction that can carry a negative flux (lower_bound < 0) is split into a forward reaction <id>_f and a backward reaction <id>_b, placed next to each other. Details¶

  • The rows 1..len(mets) are S v = b, fixed to rbnds.lb. The other rows are <= rbnds.ub, except the last row (the enzyme capacity), which is <= C.
  • The columns have the bounds of cbnds. The first len(rxns) columns are the fluxes; the others are the enzyme and auxiliary variables of MOMENT.
  • The objective rxns$ocf (the biomass reaction) is maximized.

The example files are the E. coli iAF1260 MOMENT model: 6705 rows (1674 metabolites) and 4991 columns (3234 fluxes), with glucose uptake (REV_EX_glc(e)) open. With C = 0.27 the growth rate is 0.508 1/h and the glucose uptake 12.6 mmol/gDW/h.

Differences from R¶

  • R fixes the size of the problem in the code (6705 rows, 1674 metabolites, 4991 columns, 3234 fluxes). Python takes it from the inputs, and these are the sizes of the example files.
  • The file mat.csv has no header line. The comments of the R source read it with read.table(..., header=T), which takes the first entry of the matrix as the header and so drops it. read_moment_files reads it as data.
  • Six lines of mets.csv (alcohols added at the end, e.g. isobutanol) have one field more. read_moment_files drops the extra field.
  • With cplexAPI, R also sets the upper bounds of five exchange columns (acetate, pyruvate, fructose, lactate: 0; glucose: 1000). These are the values already in cbnds.csv, so both R solvers, and Python, solve the same problem.
  • The budget can be changed (C), and the LP file is only written when lp_fname is given.

15. addGlcTrns: glucose transport constraint¶

R help page: man/addGlcTrns.Rd. Python: ccfbapy/addGlcTrns.py, functions addGlcTrns() and glc_trns_capacity().

Description¶

Adds a glucose transport constraint to the problem: an upper bound on glucose consumption, based on the kinetics of the S. cerevisiae hexose transporters.

The R function is not complete. The code that adds the transporter columns is commented out, so trnsCol is NULL and the new row cannot be built. The Python version adds the columns, as that commented-out code intended.

↑ Back to contents

Usage¶

R:

↑ Back to contents

Arguments¶

Argument Description
prob optlang problem, changed in place: e.g. res['prob'] of cfba_moment / ccFBA_mr, solve_ccFBA_mat(...)['prob'], or model.solver of a cobra model (FBA)
mod2 accepted for compatibility with R, not needed: the flux variable is found by name

transporters transporters to include, default Hxt1–Hxt7 (as in R). Add 'Gal2' when galactose is present.

trnsCol optional dict transporter → name of an existing variable of prob, used instead of a new variable

↑ Back to contents

Details¶

For each transporter t, the capacity is kcat_t * Si / (Si + Km_t):

Transporter Gene kcat Km Capacity at Si = 0.2
Hxt1 YHR094C 41 107 0.0765
Hxt2 YMR011W 16.1 2.9 1.0387
Hxt3 YDR345C 18.5 29 0.1267
Hxt4 YHR092C 12 6.2 0.3750
Hxt5 YHR096C 14 10 0.2745

Hxt7 YDR342C 11.7 1.3 1.5600

The kcat and Km values are those of the R code. The R code does not state their units. The genes are the standard names of these transporters. They all appear in the GPR rule of R_GLCt1.

The function adds, for each transporter without an entry in trnsCol, a variable trns_<t> with 0 <= x_t <= trns_ub, and the constraint

glcTrns:   v(glc_rxn) - sum_t capacity_t * x_t <= 0

With the default trns_ub = 1000, the limit is 1000 × 4.79 = 4793, so the constraint does not limit the uptake. With trns_ub = 1 the glucose uptake is at most 4.79. The R code asks whether the transporters should also take part in the enzyme budget (# Add to crowding constraint (same budget), Molecular weights required?). That is not done, in R or in Python. To link the transporters to existing variables, use trnsCol.

Details¶

The problem object is built to perform cost constrained flux balance analysis with a given model. This is a linear programming problem:

max  c^T v
s.t. S v = 0
     a_i <= v_i <= b_i      for i = 1, ..., n
     + the ccFBA constraints (kcat, complexes, multi-functional enzymes, budget)

S is the stoichiometric matrix, a_i and b_i are the lower and upper bounds of flux (variable) i, and n is the number of variables. The solution is a flux distribution that maximizes the objective c^T v in the given environment, at steady state.

How the data sets were made¶

The development tool tools/make_package_data.py of the repository prepares ccfbapy/data. It copies the CSV tables of data/ and the files of R/sybilccFBA/inst/extdata, compresses the SBML models of models/ (bigg/*.xml.gz), and exports the data sets of the R package to sybilccFBA/: the models with cobra.io.write_sbml_model (gzip), the tables as CSV. Only this export reads .RData files: it needs pip install rdata and tools/sybil2cobra.py, not the package.

Each export is read again and compared with the R data set:

  • models: reaction, metabolite and gene ids and their order, bounds, stoichiometry, GPR rules, objective, names and formulas, and the FBA optimum;
  • tables: all values, exactly (the package reads the CSV files with float_precision='round_trip').

Three things SBML cannot store as in R:

  • in the R data sets of iAF1260 and iMM904 the metabolites have no compartment (met_comp is NA, ids such as M_glc_D_c[NA]). SBML needs one: it is taken from the id (the letter before [, e.g. c); the ids are kept;
  • SBML writes the GPR rules without redundant parentheses ((A and B) and C becomes A and B and C, the same rule);
  • a missing metabolite charge (iAF1260) is read as 0.

None of them changes the results.

Per function¶

  • cfba_moment: no mod2, runFVA, fvaRxn. objVal is ignored and RHS=None gives no budget constraint, not the minimum budget.
  • cfba_moment_mr → ccFBA_mr: also no C_mu_coef. The multi-functional enzyme constraints are sum <= g (R: =). Returns fewer results (no rxnMC, rxnGeneMC, actual_C, ...).
  • getGpr1iso: arguments (model, MW, cpx_stoich=None); R: (model, cpx_stoich, MW).
  • getccFBA_mat: with RHS=None, the constraint on the objective has an effect (in R it is written to a wrong row). Reactions that are not selected get no enzyme column.
  • getccFBA_sol, simulate_EColi: the enzyme concentration of a reaction is x[exprCol] / r1gstoich. R divides by the stoichiometry of each gene.
  • simGeneOverExpr: when the gene has no concentration variable, the budget is reduced by y_pct (R stops with an error).
  • calc_MW: returns numbers (R: text). A .faa file with a single protein is handled. nchrm defaults to the number of files.
  • readmodel: the size of the problem is taken from the inputs (fixed in R). The budget C can be changed. The LP file is only written when lp_fname is given. Returns a dict (R: the vector of column values, res['x']). read_moment_files reads mat.csv without a header, so the first entry is not lost as with read.table(header=T).
  • addGlcTrns: completed. The R function cannot run because the transporter columns are never added. Python adds them (trns_<t>, bound trns_ub) and has options for the reaction, Si, the transporters and existing variables (trnsCol).
  • cfba_moment_pw: built as a matrix and solved with solve_ccFBA_mat. s0001 is removed from all OR rules. Nested rules are expanded. It works without RHS/objVal (no budget). The option pairwise=False writes one row per rule.
  • All the functions of the R package are ported, except the class sysBiolAlg_ccFBA (replaced by solve_ccFBA_mat) and getRevFlux (not needed).

Known issues¶

  • ccFBA_mr with selected_rxns: the problem is solved, but collecting geneConc fails with a KeyError for the genes that are not in any selected reaction.
  • cfba_moment and ccFBA_mr read the kcat value from the second column of Kcat and only match rxn_id with the R_ prefix. A table without the prefix (e.g. from allKcats_upd34_dd_h.csv) gives medval for every reaction, with no warning. See Kcat.
  • cfba_moment and ccFBA_mr: the pseudo gene s0001 gets a concentration variable with no cost, so reactions with rules like b0875 or s0001 are not limited in practice. R removes s0001 from these rules (see conventions).
  • simulate_EColi(atpmz=True) only finds a reaction with the id ATPM (not R_ATPM of the iAF1260/iMM904 data sets).
  • test_moment.ipynb and test_ccFBA_mr.ipynb use Windows paths with lower case file names (data\ecoli_kcat.csv). The files are data/Ecoli_kcat.csv and data/Ecoli_MW.csv, which matters on case sensitive file systems (Linux).
